# API टोकन की अनुमतियाँ

प्लगइन केवल सीमित दायरे वाले API टोकन स्वीकार करता है। Global API Keys अस्वीकार की जाती हैं और प्लगइन कभी खाते का ईमेल नहीं माँगता। इसका हर अनुरोध केवल पढ़ने का होता है; लिखने की अनुमति आवश्यक नहीं है। नीचे दिए अनुमति नाम Cloudflare के दस्तावेज़ों के लेबल हैं, जिन्हें [research/cloudflare-api-facts.md](../../../research/cloudflare-api-facts.md#3-token-permissions) में दर्ज किया गया है।

<a id="milestones-1-and-2"></a>
## पड़ाव 1 और 2

| अनुमति | दायरा | आवश्यक | उपयोग |
|---|---|---|---|
| `Cloudflare Tunnel Read` | खाता | हाँ, या नीचे दिया कोई समकक्ष | Verify में टनल की जाँच और टनल खोज |
| `Zone Read` | ज़ोन | नहीं | Verify में ज़ोन की जाँच। अभी इसका और कहीं उपयोग नहीं है |

टनल एंडपॉइंट के लिए Cloudflare इनमें से कोई भी अनुमति स्वीकार करता है; संबंधित Write अनुमतियाँ भी पर्याप्त हैं:

- `Cloudflare Tunnel Read`
- `Cloudflare One Connectors Read`
- `Cloudflare One Connector: cloudflared Read`

Cloudflare API संदर्भ में ज़ोन की अनुमति `Zone Zone Read` है; अनुमति पृष्ठ पर इसे `Zone Read` कहा गया है। दोनों नाम एक ही अनुमति के हैं।

<a id="what-discovery-calls"></a>
### खोज किन इंटरफ़ेस को बुलाती है

संग्राहक दो अनुरोध करता है, दोनों `GET`, और दोनों को टनल पढ़ने की अनुमति चाहिए:

- `/accounts/{account_id}/cfd_tunnel`, खाते के टनल सूचीबद्ध करने के लिए
- `/accounts/{account_id}/cfd_tunnel/{tunnel_id}/connections`, किसी टनल के कनेक्टर पढ़ने के लिए

Verify द्वारा जाँची जाने वाली टनल पढ़ने की अनुमति के अतिरिक्त खोज को कोई अनुमति नहीं चाहिए। यदि किसी रन में Cloudflare टनल सूची देने से इनकार करे, तो वह रन `auth` या `permission` के साथ विफल होता है; लगातार तीन विफल रन खाते के सक्रिय टनल को `unavailable` चिह्नित करते हैं, जब तक सूची फिर सफलतापूर्वक प्राप्त न हो जाए।

टोकन सत्यापन (`/tokens/verify`) के लिए अनुमति आवश्यक नहीं है। खाते के स्वामित्व और उपयोगकर्ता के स्वामित्व वाले दोनों टोकन काम करते हैं। उपयोगकर्ता टोकन को खाता सत्यापन एंडपॉइंट से HTTP 401 मिलता है, जिसके बाद प्लगइन उपयोगकर्ता एंडपॉइंट पर पुनः प्रयास करता है।

<a id="what-verify-reports"></a>
### Verify क्या बताता है

Verify परिणाम खाते पर दर्ज करता है और संपादन पृष्ठ पर Connection Status के अंतर्गत दिखाता है:

- **ok**: टोकन सक्रिय है और टनल की जाँच सफल रही।
- **permission_denied**: टोकन सक्रिय है, लेकिन टनल की जाँच अस्वीकार हुई, या दोनों टोकन सत्यापन एंडपॉइंट ने HTTP 403 दिया। ऊपर दी गई टनल अनुमतियों में से एक जोड़ें।
- **Permission: tunnel_read** और **Permission: zone_read**: दोनों जाँचों तक पहुँचने वाले नवीनतम Verify में प्रत्येक जाँच को अनुमति मिली थी या नहीं। खाता ID, टोकन, टोकन भंडारण या टोकन फ़ाइल बदलने पर ये परिणाम मिट जाते हैं।

ज़ोन अनुमति न होने से Verify विफल नहीं होता।

<a id="milestone-4-analytics-planned"></a>
## पड़ाव 4: विश्लेषिकी (नियोजित)

विश्लेषिकी संग्रह लागू नहीं हुआ है। “Collect Analytics” सेटिंग सहेजी जाती है, लेकिन अभी उसे कोई पढ़ता नहीं है। विश्लेषिकी उपलब्ध होने पर संभवतः ये अनुमतियाँ चाहिए होंगी:

| अनुमति | दायरा |
|---|---|
| `Account Analytics Read` | खाता |
| `Analytics Read` | ज़ोन |

Cloudflare की GraphQL मार्गदर्शिका टोकन को Account Analytics Read देती है, और अनुमति पृष्ठ Analytics Read को ज़ोन अनुमतियों में रखता है। ज़ोन-स्तरीय `httpRequestsAdaptiveGroups` क्वेरी को इनमें से कौन-सी अनुमति अनिवार्य रूप से चाहिए, यह सत्यापित नहीं किया गया है।

<a id="creating-the-token"></a>
## टोकन बनाना

Cloudflare डैशबोर्ड में कस्टम API टोकन बनाएँ, चाहे उपयोगकर्ता का हो या खाते का। इसे Account > Cloudflare Tunnel > Read और वैकल्पिक रूप से Zone > Zone > Read दें। खाता संसाधनों को उस खाते तक सीमित रखें जिसकी निगरानी करेंगे; यदि Zone Read जोड़ा है, तो ज़ोन संसाधनों को उसी खाते के ज़ोन तक सीमित रखें। टोकन को README में बताए अनुसार सहेजें।
